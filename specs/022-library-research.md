## 2. Core Database Drivers

### 2.1 pgx — PostgreSQL Driver

| | |
|---|---|
| **Module** | `github.com/jackc/pgx/v5` |
| **Latest** | v5.9.1 (March 2026) |
| **Go version** | 1.25+ |
| **Stars** | 13.6k |
| **License** | MIT |

**Verdict: Use.** De facto standard Go Postgres driver.

| Feature | Support | Notes |
|---|---|---|
| Connection pooling (`pgxpool`) | Yes | Full pool with health checks, hooks, stats |
| `SET LOCAL` in transactions | Yes | Plain SQL, auto-resets at COMMIT/ROLLBACK |
| `FOR UPDATE SKIP LOCKED` | Yes | Plain SQL |
| LISTEN/NOTIFY | Yes | Requires dedicated `*pgx.Conn` (not pool) |
| Prepared statements | Yes, disableable | Use `QueryExecModeSimpleProtocol` for Supavisor |
| `database/sql` interface | Yes, via `stdlib` | But native interface preferred for full features |
| Savepoints | Yes | `tx.Begin()` on existing tx creates savepoint |

**Gotchas:**
- `WaitForNotification` needs a dedicated `*pgx.Conn`, not `pgxpool.Pool`
- Prepared statements break with Supavisor transaction mode — must disable
- `pgx.Conn` is NOT concurrency-safe — always use `pgxpool` for concurrent access
- v5.9.x requires Go 1.25+ — pin to v5.7.x if older Go needed

**Supabase Cloud configuration:**
```go
config, _ := pgxpool.ParseConfig(connString)
config.ConnConfig.DefaultQueryExecMode = pgx.QueryExecModeSimpleProtocol
```

### 2.2 SQLite Driver — **DECISION REQUIRED**

| | modernc.org/sqlite | mattn/go-sqlite3 | ncruces/go-sqlite3 |
|---|---|---|---|
| **Latest** | v1.48.2 | v1.14.24 | v0.25.x |
| **Pure Go** | **Yes** | No (CGO) | Yes (WASM) |
| **CGO_ENABLED=0** | **Yes** | No | Yes |
| **sqlite-vec** | **No** | Yes | Partial |
| **sqlite-jsonschema** | **No** | Yes | Partial |
| **WAL mode** | Yes | Yes | Yes |
| **`database/sql`** | Yes | Yes | Yes |
| **Cross-compile** | **Easy** | Requires toolchain | **Easy** |
| **Read performance** | **Faster** | Slower | Comparable |
| **Write performance** | Slower | **Faster** | Slower |
| **Binary size** | ~30MB+ | Smaller | ~15MB |

**Critical issue:** The specs reference `sqlite-vec` for vector search and `sqlite-jsonschema` for validation. `modernc.org/sqlite` **cannot load native SQLite extensions** because it transpiles C to Go — the dynamic loading mechanism doesn't exist.

**Options:**

1. **`mattn/go-sqlite3` (CGO)** — supports all extensions, but requires CGO. Breaks `CGO_ENABLED=0` builds. Cross-compilation requires a C toolchain.
2. **`modernc.org/sqlite` (pure Go)** — no extensions, but pure Go. Would need to implement vector search and JSON Schema validation as Go code.
3. **`ncruces/go-sqlite3` (WASM)** — pure Go via WASM, growing extension ecosystem. Less mature.
4. **Skip SQLite vector search** — only use vector/embedding features on Postgres. SQLite mode works without semantic search.
5. **Dual build** — CGO build with `mattn/go-sqlite3` for full features, pure-Go build with `modernc.org/sqlite` for zero-dependency mode.

**Recommendation:** Option 4 — skip SQLite vector search for v1. The SQLite backend is for local development and single-user scenarios. Vector search is a production feature that belongs on Postgres. For JSON Schema validation, implement in Go application layer. This keeps the build pure-Go with `modernc.org/sqlite`. If vector search on SQLite becomes critical later, migrate to `mattn/go-sqlite3` with a build tag.

## 5. HTTP & API Layer

### 5.1 Router: go-chi/chi/v5

| | |
|---|---|
| **Module** | `github.com/go-chi/chi/v5` |
| **Latest** | v5.2.5 (February 2026) |
| **Dependencies** | **Zero** |
| **Stars** | 22k |
| **License** | MIT |

**Why chi over alternatives:**
- Zero dependencies — `go.mod` is just `go 1.23`
- 100% `net/http` compatible — handlers are `http.HandlerFunc`
- SSE works naturally (direct access to `http.ResponseWriter` + `http.Flusher`)
- Route groups, inline middleware, sub-router mounting
- ~1000 LOC core. Production-proven at Cloudflare, Heroku.

**Not chosen:** Gin (custom `gin.Context`, not `net/http` compatible), Echo (same issue), stdlib alone (no route groups).

### 5.2 Server-Sent Events: Raw `net/http` (no library)

`r3labs/sse` is unmaintained. SSE in Go is simple enough with raw `net/http`:

```go
func handleSSE(w http.ResponseWriter, r *http.Request) {
    flusher, _ := w.(http.Flusher)
    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.Header().Set("Connection", "keep-alive")

    sub := broker.Subscribe()
    defer broker.Unsubscribe(sub)

    for {
        select {
        case <-r.Context().Done():
            return
        case msg := <-sub.Ch():
            fmt.Fprintf(w, "event: %s\ndata: %s\n\n", msg.Event, msg.Data)
            flusher.Flush()
        }
    }
}
```

Go's `r.Context().Done()` fires automatically on client disconnect. No library needed.

## 7. Configuration

### 7.1 YAML: `go.yaml.in/yaml/v3`

**Verdict: Use raw YAML.** Not Viper.

Viper pulls in 8+ dependencies for features we don't need (hot-reload, TOML, INI, remote config). For "load a YAML file into a struct":

```go
data, _ := os.ReadFile("consensus.yaml")
var cfg Config
yaml.Unmarshal(data, &cfg)
```

Add env var and flag overrides manually. Simpler, zero surprise dependencies.

## 10. Open Issues

### 10.1 SQLite Vector Search

`modernc.org/sqlite` cannot load `sqlite-vec`. Options:

1. **Skip vector search on SQLite** (recommended for v1) — SQLite is for local dev. Vector search is a Postgres production feature.
2. **Implement vector search in Go** — brute-force KNN over embedding arrays. Adequate for <10K vectors.
3. **Dual build tags** — `mattn/go-sqlite3` with CGO for full features, `modernc.org/sqlite` for pure-Go builds.
4. **`ncruces/go-sqlite3`** — WASM-based, growing extension support. Less mature.

### 10.2 SQLite JSON Schema Validation

Same issue — `modernc.org/sqlite` can't load `sqlite-jsonschema`. Options:

1. **Validate in Go application layer** before INSERT/UPDATE. Works for both backends.
2. **Use CHECK constraints** for simple validation instead of full JSON Schema.

Recommendation: validate in Go layer. Keeps both backends consistent and avoids extension dependency.

### 10.3 pgx Go Version Requirement

pgx v5.9.x requires Go 1.25+. If we need to support older Go versions, pin to v5.7.x. For a new project starting in 2026, Go 1.25+ is reasonable.

### 10.4 MCP SDK Pre-1.0

`mcp-go` is at v0.47.1 — not yet v1.0. API may change. Pin version in `go.mod` and update deliberately, not automatically.
