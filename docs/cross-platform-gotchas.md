# Consensus — Cross-Platform Quickstart Gotchas

> Generated by UX-007 foreman-direct investigation, 2026-07-22.
> Covers Linux (native/Docker), macOS, and Windows (WSL2).

## tl;dr

Consensus is a Go binary with a pure-Go SQLite driver (`modernc.org/sqlite`).
It compiles and runs on Linux, macOS, and Windows with zero code changes.
The quickstart flow (`go build → init → serve`) works on all three platforms
with minor footnotes below.

## Baseline: Linux (reference)

Everything works. Build, init, serve, health, Chronicle UI — all green.

```bash
go build -o bin/consensus ./cmd/consensus/
./bin/consensus init --db-url "sqlite://$HOME/.consensus/consensus.db"
./bin/consensus serve
curl http://localhost:8090/api/v1/health  # → healthy
```

Cross-compilation to macOS and Windows works with CGO disabled:

```bash
CGO_ENABLED=0 GOOS=darwin  GOARCH=amd64 go build ./cmd/consensus/
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./cmd/consensus/
```

## macOS Gotchas

### 1. `open` command (minor — docs only)

The README uses `open http://localhost:8090/chronicle/`. This works on macOS
natively. No action needed for macOS users. For cross-platform README
completeness, the user already knows to use `open` or `xdg-open`.

### 2. Docker Desktop I/O Performance

Docker Desktop on macOS uses a Linux VM with osxfs for bind mounts. SQLite
write-heavy workloads (WAL mode, append-only memory ledger) can be
significantly slower than native Linux.

**Workaround:**
- Use `cached` or `delegated` mount consistency: `-v consensus-data:/home/consensus/data:cached`
- For development, run the Go binary natively (no Docker)
- Docker Desktop 4.30+ includes VirtioFS which improves performance

### 3. macOS Gatekeeper (unsigned binary)

If distributing a pre-compiled binary, macOS Gatekeeper will block it:

```
"consensus" cannot be opened because the developer cannot be verified.
```

**Workaround:** Right-click → Open, or `xattr -d com.apple.quarantine ./bin/consensus`

### 4. Default SQLite DB Path

`$HOME` resolves to `/Users/<username>` on macOS. The default DB path
`$HOME/.consensus/consensus.db` works correctly. No special handling needed.

### 5. Go Toolchain

macOS users need Go 1.26+ installed (`brew install go`). Both Intel and
Apple Silicon (arm64) work. Cross-compilation target is `GOOS=darwin`.

## Windows (WSL2) Gotchas

### 1. WSL2 is the Recommended Path

Consensus is tested on Linux. On Windows, run inside WSL2 (Ubuntu recommended).
Everything works identically to native Linux. Docker Desktop with WSL2 backend
provides near-native performance.

**Not recommended:** Running the Go binary directly on Windows (cmd.exe /
PowerShell). It'll compile and run, but terminal UX (ANSI colors, signal
handling) is inferior.

### 2. WSL2 File Path Gotcha

When the project lives on the Windows filesystem (`/mnt/c/Users/...`), SQLite
file locking can be unreliable due to the 9p/DrvFs translation layer.

**Workaround:** Clone and run inside the WSL2 Linux filesystem:
```bash
cd ~/projects  # Linux filesystem, not /mnt/c/
git clone https://github.com/totalwindupflightsystems/consensus.git
cd consensus
```

### 3. Native Windows (non-WSL)

If running natively on Windows without WSL:

- **SQLite DSN:** Use forward slashes even on Windows:
  ```
  sqlite://C:/Users/username/.consensus/consensus.db
  ```
  Backslashes (`C:\Users\...`) may not parse correctly in DSN URLs.

- **Terminal:** Use Windows Terminal or PowerShell 7+. Older cmd.exe and
  PowerShell 5.x have limited ANSI escape code support. The Chronicle UI
  (browser-based) is unaffected.

- **Signal handling:** Windows lacks SIGTERM. Consensus relies on
  `os/signal` which Go maps to Windows equivalents (`os.Interrupt` →
  CTRL+C, `os.Kill` → TerminateProcess). Graceful shutdown works via
  CTRL+C but `kill` is not available.

- **Port 8090 conflicts:** Windows has more background services that may
  occupy port 8090. Use `--port` flag or `CONSENSUS_PORT` env var.

### 4. Docker Desktop Mode

Docker Desktop on Windows has two backends:
- **WSL2 (recommended):** Near-native Linux performance. Use this.
- **Hyper-V (legacy):** Significantly worse I/O. Avoid for Consensus workloads.

Check: `docker info | grep -i "backend\|OSType"`

### 5. API Key Persistence

Windows users setting `DEEPSEEK_API_KEY` via:
- WSL2: `export` in `~/.bashrc` (same as Linux)
- PowerShell (native): `$env:DEEPSEEK_API_KEY = "sk-..."` in `$PROFILE`
- cmd.exe (native): `setx DEEPSEEK_API_KEY "sk-..."`

## Platform-Independent Gotchas

### 1. Port 8090 Conflicts

The default port 8090 can conflict with other services on any platform.
Known conflict: Dagger Engine. Use `--port` or `CONSENSUS_PORT` to override.

### 2. SQLite Concurrency

`modernc.org/sqlite` supports concurrent reads but serializes writes.
This is consistent across platforms. For high-concurrency write workloads,
use the PostgreSQL backend.

### 3. API Key in Shell History

`consensus init` generates an admin key. On all platforms, avoid passing
API keys as command-line arguments (they appear in shell history):

```bash
# Bad: appears in ~/.bash_history / ~/.zsh_history
./bin/consensus init --llm-key "sk-..."

# Good: use env var or prompt
export DEEPSEEK_API_KEY="sk-..."
./bin/consensus init
```
