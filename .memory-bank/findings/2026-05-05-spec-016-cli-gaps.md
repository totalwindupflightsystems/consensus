# SPEC-016 CLI Interface Gaps

**Date:** 2026-05-05
**Severity:** medium
**Source:** Idle spec conformance sweep-019 against `specs/016-cli-interface.md`
**Remediation:** `spec-016-hardening-01`
**Status:** queued

---

## Summary

Sweep-019 audited the CLI implementation (10 commands across `internal/cli/`) against SPEC-016 and found 8 gaps: 5 HIGH, 2 MEDIUM, 1 LOW.

## Findings

### HIGH

1. **HARDEN-CLI-01** — Config file priority chain: only `./conscience.yaml` checked. Missing `~/.conscience/config.yaml` and `/etc/conscience/config.yaml`. `--config` global flag is declared but never consumed (dead flag).

2. **HARDEN-CLI-02** — Interactive approval mode (`conscience approve` with no args) not implemented despite detailed spec in §5.4.

3. **HARDEN-CLI-03** — Five subcommands are non-functional stubs returning hardcoded errors: `migrate run`, `migrate rollback`, `migrate create`, `config set`, `memory pages`.

4. **HARDEN-CLI-04** — `conscience status` uses `Println()`/`PrintText()` bypassing the structured formatter. `--format json` has no effect.

5. **HARDEN-CLI-05** — 21 command-specific flags from the spec are missing across 9 commands.

### MEDIUM

6. **HARDEN-CLI-06** — Approve command naming: spec uses `conscience approve <id>` / `conscience reject <id>`; implementation uses `conscience approve accept/reject <id>`.

7. **HARDEN-CLI-07** — Migrate: spec says `conscience migrate` (bare) runs migrations; implementation requires `conscience migrate run`.

### LOW

8. **HARDEN-CLI-08** — `config get` only supports top-level keys, not nested dot notation (e.g., `llm.default_model`).

## Resolution

Queued as `spec-016-hardening-01` in the gap remediation queue. Priority: address after `spec-003-hardening-01`, `spec-013-hardening-01`, `spec-014-hardening-01`.
