# Finding: SPEC-006 Transaction Infrastructure Gaps

## Summary
The idle spec conformance sweep of `specs/006-transactions.md` found that the core transaction loop, error handling, and audit logging are fully implemented, but three supporting subsystems have meaningful gaps: circuit breaker persistence, billing write path, and async tool execution.

## Details

**Core (PASS):**
- Transaction loop (BEGIN/COMMIT/ROLLBACK): `internal/harness/executor.go:84-155` — fully implemented
- Error handling (rollback + inject into next context): `executor.go:239-285` — fully implemented
- Audit log writing (monologue, SQL, result): `internal/harness/audit.go:33-71` — fully implemented
- Error classification (syntax/semantic/constraint/RLS/destructive): covered by SQL classifier + executor

**Gaps found (4 categories):**

1. **`agent_circuit_breakers` table missing** — The spec (§Circuit Breakers, line 156) calls for a dedicated table with `breaker_type`, `threshold`, `current_count`, `tripped_at`. The Go code has a `checkCircuitBreaker` function (`executor.go:293`) that does simple numeric comparison, but never persists tripped state. The table does not exist in any migration.

2. **Billing write path missing** — `internal/billing/doc.go` is a stub (1 line of package doc). No Go code writes `prompt_tokens`, `completion_tokens`, or `cost_usd` to the `agent_billing` table after LLM calls. The table exists in the schema whitelist and the API layer reads from it for dashboards, but nothing populates it. Budget-limit enforcement before LLM calls is also absent.

3. **Async tool executor missing** — Phase 1 (write `tool_requests` as pending in cognition TX: `executor.go:123-132`) is implemented. Phase 2 (poll `tool_requests` for pending rows, execute sandboxed, write `tool_results`) is a stub at `executor.go:175-178`. `internal/tools/tools.go` defines types but no polling/execution loop.

4. **Stored procedure equivalents partial** — `spawn_subagent` exists as Go function. `archive_memory()` and `approve_tool()` are not implemented anywhere. `complete_task()`/`cancel_task()` exist only as sub-agent-specific variants, not general purpose.

- **Trigger**: Idle spec conformance sweep-003 against `specs/006-transactions.md`.
- **Impact**: Cost tracking is non-functional (no billing records written). Circuit breakers cannot persist tripped state across restarts. Tools requested by agents are never executed asynchronously. Budget limits displayed but not enforced.
- **Root cause**: These were deferred during the initial build sprints (runtime-harness-01, deployment-ops-01) to focus on the core loop. They were not picked up later.

## Prevention / Fix
- Remediation work item created: `spec-006-hardening-01`
- Add a `BeforeLLMCall` hook in the harness that checks cumulative billing against budget limits and writes billing rows after each call
- Create the `agent_circuit_breakers` table in a new migration and persist tripped state there
- Implement a tool executor goroutine in the harness that polls `tool_requests.status='pending'` and dispatches to sandboxed subprocesses
